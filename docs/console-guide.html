Models-as-a-Service · OpenShift console

Publishing and pricing models from the OpenShift console

Two templates turn a deployed model into a governed, priced MaaS endpoint by filling in a form. No YAML or command line is needed after the one-time setup.

Overview 1. One-time setup 2. Publish a model 3. Add a subscription tier 4. Verify 5. Change or remove 6. Troubleshooting

Overview

A model becomes usable through MaaS in two steps. You publish it once, then add one subscription tier for each group of users who need it. Each tier sets a token quota and a price.

Deployed modelLLMInferenceService in a project, e.g. demo-llm
→
MaaS 1 · Publish a modelOnce per model
→
MaaS 2 · Subscription and pricingOnce per tier: Premium, Basic, …
Template · maas-publish-model

MaaS 1 - Publish a model

  • MaaSModelRef in the model's project. Puts the model behind the MaaS gateway.

Skip it if the model was already published as a MaaS endpoint from the OpenShift AI dashboard.

Template · maas-model-subscription-pricing

MaaS 2 - Model subscription and pricing

  • MaaSSubscription: token limits per minute, hour and day
  • MaaSAuthPolicy: lets the group call the model
  • PrometheusRule: the price, for the cost dashboard

The subscription and the auth policy always come together. Without the policy, the gateway refuses the group with 403. Without the subscription, the group gets through but has no token budget and every request returns 429.

Token limits are per user

Each member of the group gets the full limit. A group of 50 people on a 20,000 tokens/minute tier can use up to 50 × 20,000 tokens per minute in total.

01One-time setup

A cluster administrator does this once per cluster. It takes about five minutes.

1a. Let the console create and remove MaaS subscriptions

When you click Create on a template form, OpenShift's template controller creates the objects for you. When you delete the instance, a second controller removes them. Both can handle MaaSModelRefs and PrometheusRules, but not MaaSSubscriptions or MaaSAuthPolicies. This role adds those two and nothing else, and it is bound only to the two controllers. Users gain no new rights, and the controller still checks that the person instantiating is allowed to create each object.

  1. In the console masthead, click the + icon (Import YAML).
  2. Paste the contents of maas-template-instance-governance-rbac.yaml and click Create.
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRole
metadata:
  name: maas-template-instance-governance
rules:
- apiGroups: ["maas.opendatahub.io"]
  resources: ["maassubscriptions", "maasauthpolicies"]
  verbs: ["get", "list", "watch", "create", "update", "patch", "delete", "deletecollection"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRoleBinding
metadata:
  name: maas-template-instance-governance
roleRef:
  apiGroup: rbac.authorization.k8s.io
  kind: ClusterRole
  name: maas-template-instance-governance
subjects:
- kind: ServiceAccount
  name: template-instance-controller
  namespace: openshift-infra
- kind: ServiceAccount
  name: template-instance-finalizer-controller
  namespace: openshift-infra

Skip this and tiers can be neither created nor removed

Creating a tier fails with InstantiateFailure: maassubscriptions.maas.opendatahub.io is forbidden: User "system:serviceaccount:openshift-infra:template-instance-controller" cannot create …. The price rule is still created, so delete the failed instance before retrying.

Deleting a tier hangs. The instance stays in the list, its subscription and auth policy stay in place, and its API keys keep working.

1b. Add the two templates

Add them to the models-as-a-service project. This keeps them next to the subscriptions they create and visible only to people with access to that project.

  1. Select project models-as-a-service in the project selector.
  2. Click + (Import YAML), paste maas-publish-model-template.yaml, and click Create.
  3. Repeat with maas-model-subscription-pricing-template.yaml.

Both now appear in the software catalog of that project as MaaS 1 - Publish a model and MaaS 2 - Model subscription and pricing.

1c. Create the user groups

Each tier is granted to one OpenShift group. Create the groups under User Management → Groups and add the users. With an external identity provider (Keycloak, Entra ID), the group name in the template must match the group claim in the user's token exactly.

02Publish a model

Do this once per model, after the model is deployed and running.

Already published from the OpenShift AI dashboard?

If the model was deployed with the MaaS endpoint option turned on, it is already published. Go to section 3. Instantiating this template would fail with already exists. To check, open Home → Search, choose resource MaaSModelRef, and look for the model's name in its project.

Open the form

Either:

  • Select project models-as-a-service, open the software catalog, filter by type Template, choose MaaS 1 - Publish a model, and click Instantiate Template. Or:
  • Open this address directly (replace the console host): 
    https://<console-host>/catalog/instantiate-template?template=maas-publish-model&template-ns=models-as-a-service&preselected-ns=models-as-a-service

Leave Namespace at the top of the form as models-as-a-service. That is only where the record of this instance is kept; the MaaSModelRef goes into the model's own project.

Why cents?

At pilot volumes, prices in dollars round to zero on the dashboard: 1,000 tokens at $2.00 per million is $0.002. The same price as 200 cents per million shows as 0.2.

04Verify

  1. The instances succeeded. Home → Search, project models-as-a-service, resource TemplateInstance. Open each one: the condition should be Ready with reason Created, and the Objects list shows what was created.
  2. The model is live. Search resource MaaSModelRef in the model's project. Phase is Ready once the model pods are running. While pods are still starting it shows Pending or Unhealthy; wait.
  3. The tier is active. Search MaaSSubscription and MaaSAuthPolicy in models-as-a-service. Both show Active.
  4. A user can call the model. A member of the group creates an API key for the new subscription and sends a request. The model list (/v1/models) shows the display name and description you entered.
  5. Cost shows up. One to two minutes after the first requests, the tier appears on the MaaS cost dashboard under its subscription name.

Validated on OpenShift 4.21 with OpenShift AI 3.5

Tested with one model published by template 1 and two tiers added by template 2 (Premium 20,000 and Basic 100 tokens/minute). Requests on both tiers returned 200. The Basic tier returned 429 after about 118 tokens in one minute, and the dashboard query priced each tier separately (118 tokens × 50 = 0.0059 USc; 172 tokens × 200 = 0.0344 USc). Deleting a tier's instance removed all three objects, and that tier's API keys then returned 403.

05Change or remove

Change limits or price

The form cannot be re-run against an existing tier. Edit the object directly:

  • Limits, group or priority: Home → Search → MaaSSubscription → the tier → YAML tab. Change spec.modelRefs[0].tokenRateLimits and save. If you change the group, change it in the matching <name>-access MaaSAuthPolicy too.
  • Price: PrometheusRule maas-price-<subscription name> in redhat-ods-monitoring. Change the number in both expr lines (the price per 1M tokens) and save.

The TemplateInstance keeps showing the original form values. To keep everything consistent, remove the tier and instantiate it again with the new values.

Remove a tier

Home → Search → TemplateInstance in models-as-a-service → the tier's instance → Actions → Delete. This deletes its subscription, auth policy and price rule. The model stays published, and users' API keys for that tier stop working.

Unpublish a model

Affects every tier

Deleting the MaaS 1 instance deletes the MaaSModelRef. The model disappears from MaaS for all tiers. Remove the model's tiers first.

Instances are named by the console. Open an instance and check its Objects list to see which model or tier it belongs to.

06Troubleshooting

A failed instance shows condition InstantiateFailure with the reason in its message. Objects created before the failure are kept, so delete the failed instance before retrying.
